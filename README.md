# hexapod-web

브라우저만으로 도는 6족 보행 로봇 시뮬레이터. ROS도 Gazebo도 없이 three.js + Rapier(WASM)로
물리를 돌리고, 걸음새 파라미터를 실시간으로 튜닝한다.

빌드 스텝이 없다. importmap + CDN이라 정적 서버만 있으면 된다.

```bash
npx serve . -l 5173
```

기구학과 걸음새는 브라우저 없이도 검증된다.

```bash
node test.mjs
```

## 조작

| 키 | 동작 |
|---|---|
| `W` `A` `S` `D` | 전진 / 게걸음 |
| `I` `K` | 몸통 높이 |
| `J` `L` | 좌 / 우 선회 |

화면 오른쪽 아래 스틱 두 개를 마우스로 끌어도 된다. 왼쪽 사이드바 슬라이더는 스틱을
끝까지 밀었을 때의 기준값과 서보·물리 파라미터를 만진다.

## 구조

| 파일 | 역할 |
|---|---|
| `ik.js` | 다리 IK/FK와 프레임 변환. 의존성 없음 |
| `gait.js` | tripod 발끝 궤적. 궤적을 바꾸려면 `shape()` 하나만 갈아끼우면 된다 |
| `robot.js` | Rapier 조립, collider, 서보 모터 |
| `joystick.js` | 아날로그 스틱 (키보드 + 포인터) |
| `main.js` | 렌더, UI, 루프. `window.sim` 으로 디버그 훅 노출 |
| `test.mjs` | 기구학·걸음새 자체 검증 |

물리는 항상 primitive collider(box / capsule / ball)로 돈다. 나중에 메시를 입히더라도
visual 로만 덮어야 하고, collider 를 메시로 바꾸면 안 된다 — 느리고 불안정하다.

## 파라미터 튜닝

기본값은 감으로 정하지 않았다. `window.sim.headless(초)` 가 화면 렌더 없이 물리만
돌려주므로, 콘솔에서 파라미터를 바꿔가며 스윕해서 뽑았다. 로봇 형상이나 질량을
바꾸면 반드시 다시 뽑아야 한다 — 서보 게인과 물리 주파수까지 같이 움직인다.

현재 기본값 실측(총 3.55 kg):

| | |
|---|---|
| 전진 | 0.137 m/s (보폭 효율 100% — 발이 미끄러지지 않는다) |
| 8초 직진 시 이탈 | 측면 1.3 cm, yaw 0.2° |
| 몸통 상하 진동 | 정상 주행 1.2 mm, 정지 0.2 mm |
| 진동 주파수 | 2 Hz 대 — tripod 교대 주기 그 자체 |
| 물리 비용 | 60 fps 예산의 15% |

전진과 선회를 같이 주면 곡선으로 돈다 (4초에 전진 0.25 m + 62°).

## 만들면서 밟은 함정

측정으로 찾은 것들이라 코드 주석에도 남겨뒀다.

- **부호 규약이 두 곳에 흩어지면 테스트가 못 잡는다.** IK/FK 가 수학 표준(`atan2(z,x)`,
  +q1 이 +Z)을 쓰고 three.js/Rapier 는 `R_y` 규약(+θ 가 −Z)을 쓰는데, 둘 다 같은 규약이라
  IK/FK 왕복 테스트는 멀쩡히 통과하면서 로봇만 반대로 걸었다. 정지 자세는 로컬 z=0 이라
  증상조차 안 나타난다. 같은 이유로 다리가 몸통을 가로질러 교차한 적도 있다.
  회전 규칙은 `ik.js` 한 곳에만 두고, FK 가 `R_y` 와 같은 방향인지 직접 대조하는 테스트를 두었다.
- **발이 지면에 "닿아만" 있으면 수직항력이 없다.** IK 목표 높이를 지면에 정확히 맞추면
  마찰을 20 까지 올려도 미끄러진다. stance 발을 지면보다 조금 아래로 목표해야
  (`push`) 다리가 몸을 실제로 딛는다. 실물에서도 같은 이유로 필요하다.
- **물리 주파수가 서보 고유진동수를 못 따라가면 몸통이 떤다.** 240 Hz 에서 20~30 mm 떨던
  것이 480 Hz 에서 2.4 mm 로 잡혔다. 960 Hz 는 계산량만 2배고 나아지지 않았다.
- **서보 목표를 프레임당 한 번만 갱신하면 계단이 된다.** 스윙 발이 궤적을 32 mm 뒤처지고,
  게인을 10배 올려도 안 줄어든다. 매 물리 스텝 갱신해야 한다.
- **스윙 발을 앞으로 달리는 채로 착지시키면 몸통이 뒤로 밀린다.** 착지 속도를 stance
  속도에 맞추는 3차 에르미트로 이었다.
- **다리마다 stride 를 따로 정규화하면 선회가 사라진다.** 크기를 버리고 방향만 남기면
  전진과 선회를 동시에 줬을 때 비율이 없어져 회전 명령이 통째로 무시된다. 6개 중 가장 큰
  stride 를 보폭에 맞추고 나머지는 비율대로 줄여야 차동 조향이 나온다. 덧붙여 접선 stride 는
  `omega × mountR` 이라, 게인 없이는 회전 기여가 병진의 1/10 밖에 안 된다.
- **걸음을 계단으로 켜면 로봇이 튀어오른다.** 정지 상태에서 스윙 높이와 발 하중을 한 프레임에
  0 → 최대로 올리자 몸통이 32 mm 솟았다. 시간축에서 램프하면 7 mm 로 줄어든다.
- **Rapier 는 1 m 스케일을 가정한다.** 기본값이면 허용 관통이 1 mm 인데, 발 반지름이 16 mm 인
  로봇에는 너무 커서 발이 매 스텝 들락거리고 그게 14 Hz 떨림이 된다. `lengthUnit` 을 로봇
  스케일(0.1)로 낮추고 접촉 솔버 내부 반복(`numInternalPgsIterations`)을 1 → 4 로 올리면
  몸통 진동이 8.7 mm → 2.5 mm 로, 떨림 주파수는 14.5 Hz → 1.9 Hz(보행 리듬)로 떨어진다.
  이건 서보 게인으로는 절대 못 잡는다 — 실제로 게인 스윕은 재현성 없는 값만 뱉었다.
- **스윙 들림 곡선도 착지 속도가 0 이어야 한다.** `sin(pi*a)` 는 착지 지점에서 기울기가
  최대라 발이 0.5 m/s 로 내리꽂힌다. `(1-cos(2*pi*a))/2` 는 최고점은 같으면서 양 끝
  수직 속도가 0 이다.
- **조종 입력은 축마다 다른 속도로 램프해야 한다.** 몸통 높이를 스틱 속도(0.1 초에 3 cm)로
  따라가게 두면 서보가 급하게 밀어올려 16 mm 오버슈트한다 — 눈에는 '붕 뜨는' 것으로 보인다.
  높이만 0.5 초 정도로 늦추면 오버슈트가 0 이 된다.
- **출발할 때 보폭을 바로 최대로 내디디면 몸이 틀어진 채 걷는다.** tripod 는 좌2/우1 이
  먼저 나가서 본질적으로 비대칭이라, 첫 스텝에서 7.5° 돌아간 뒤 그 방향으로 곧게 간다.
  8초에 측면 17 cm 이탈했다. 보폭도 스윙 높이와 같이 램프하면 1.3 cm 로 줄어든다.
  드리프트처럼 보이지만 지속적인 게 아니라 출발 한 번의 편향이므로, 폐루프 보정을
  붙이기 전에 여기부터 확인하라.
- **링크 질량을 부피×밀도로 잡으면 안 된다.** 링크마다 서보가 통째로 붙어서 실제로는
  훨씬 무겁다. 너무 가벼우면 서보 오버슈트가 그대로 떨림이 되고 솔버도 나빠진다.
